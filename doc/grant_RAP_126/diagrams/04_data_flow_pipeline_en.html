Data Flow Pipeline

How physiological data travels from sensors on the body to the VitalWork server

① Sensor sources
Physiological signals captured during each biofeedback scenario
eSense Pulse BLE ~4.5 Hz · HR / R-R
eSense Respiration Audio jack 5 Hz · resp. rate
Galaxy Watch 8 Wearable Data Layer 1 Hz · HR / IBI / EDA buffered on the watch —
merged at session end (diagram 05)
② Capture
Recording Engine Each sample is tagged with sensor type, NTP-corrected timestamp, and elapsed time within the scenario
③ Buffer
Batch Buffer eSense samples are grouped in memory and written to the database every 50 samples or every 1 second — whichever comes first
(watch data skips this buffer — it arrives in one batch at session end)
④ Store
Room Database All samples saved locally on the device in a SQLite database (sensor_samples table)
At session end, two independent paths read from the same database
⑤a Local export — manual, optional
Export Mapper Reads all rows for the session, flags any gaps in the signal
JSON + CSV Saved to the device's Documents folder as an offline local copy
⑤b Server upload — automatic
Upload Mapper Reads participant, session and scenarios; builds the HTTP payload expected by the server API
VitalWork Server POST /api/sessions/upload · bearer auth · 600 s timeout
Re-sending the same session is safe — identified by sessionCode
